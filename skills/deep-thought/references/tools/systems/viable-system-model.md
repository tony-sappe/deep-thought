# Viable system model

**Job.** Check whether an organization can stay viable: operations, coordination, control, intelligence, and identity, repeated at each level.

**Not this.** A process map, a RACI, or a messy contested purpose (soft systems). Use this when the question is whether management variety matches the variety of the work.

**Diagram.** One recursion. System 1 units inside, then 2, 3, 3*, 4, and 5. Mark which function is missing or collapsed into another.

**Steps.**
1. Name the System 1 units: the parts that do the work this system exists to do. Each should itself be viable. If you cannot name them, you do not have the recursion yet.
2. System 2: what stops those units oscillating against each other (shared schedules, standards, conflict handling)?
3. System 3: who allocates resources and holds the here-and-now together? System 3*: what audit channel sees the operation without relying only on the unit's own report?
4. System 4: who watches the outside and the future, and is that view connected to System 3 rather than isolated?
5. System 5: who closes identity and policy when System 3 and System 4 disagree? If 5 is absent, the loudest of 3 or 4 is running the organization.
6. Name one missing function. Do not recommend a new department if an existing channel can carry it.

**Source.** Stafford Beer, the viable system model. Ashby's requisite variety is the constraint underneath it. Orientation: [OpenLearn systems thinking](https://www.open.edu/openlearn/systems-thinking-hub).
