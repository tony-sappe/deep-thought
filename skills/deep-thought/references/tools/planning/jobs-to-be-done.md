# Jobs to be done

**Job.** State the progress someone is hiring this product or process to make, in a situation, so you design for the job rather than for the current feature.

**Not this.** A persona, a demographic, or a roadmap theme. If you cannot name the situation and the struggle, you do not have the job yet. Also not a substitute for a system map when the question is why a loop persists.

**Diagram.** The circumstance and the progress being hired. Under it, Intercom's job story (When / I want to / so I can) and Moesta's forces.

**Steps.**
1. Name the circumstance, not a segment label. Christensen's job is the progress the person is trying to make there.
2. Name that progress. Include the functional outcome and, when it changes the design, the social or emotional dimension.
3. Name what they hire today: your thing, a competitor, a workaround, or non-consumption.
4. Write Moesta's forces of progress: push away from the current way, pull toward the new way, habit, and anxiety.
5. Judge the design against the progress. A feature that does not change that progress in that circumstance is not yet justified.

**Source.** Clayton Christensen, jobs to be done (progress in a circumstance). Bob Moesta, the forces of progress. The When / I want to / so I can sentence is Intercom's job story.
