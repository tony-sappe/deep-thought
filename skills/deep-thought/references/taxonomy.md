# Taxonomy

Two labels, then a tool. Domain is the job. Layer is how deep the cause sits. Read this page before classifying. Tool pages are listed in [the index](tools/_index.md).

## Domains

| Domain | The job in front of you | Primary family |
| --- | --- | --- |
| Frame | What should we even ask? Deadlock. Too many questions. | Framing |
| Diagnose | Why this, not that? A cause you can act on. | Diagnosis. Add a Systems complement when the cause repeats or branches. |
| Systems | Loops, delays, unintended effects, policy resistance. | Systems |
| Decide | Choose among options. | Decision |
| Prioritize | Too much work. What first. | Prioritization |
| Plan | Sequence, risk, capacity, invention. | Planning |
| Communicate | Explain, enroll, or give feedback. | Communication |

## Signal → domain

| What the user is doing | Domain |
| --- | --- |
| "What should we even ask?" / deadlock / many questions | Frame |
| "Why does this keep happening?" / root cause | Diagnose, and Systems when it recurs |
| Loops, delays, unintended effects, policy resistance | Systems |
| Choose among options | Decide |
| Too much work / what first | Prioritize |
| Sequence, risk, capacity, designing a way through | Plan |
| Explain / enroll / feedback | Communicate |

One domain. If two are live, the eigenquestion says which one changes the next move. The other may be a complement.

## Iceberg layers

Name the layer the event is stuck on, not the layer you wish you were working at. The order is depth, from shallow to deep.

| Layer | You are looking at | What a tool has to touch |
| --- | --- | --- |
| Events | One occurrence | A fact, a defect, a decision in front of you |
| Patterns | A recurrence over time | A graph, a repeated story, a loop candidate |
| Structure | Stocks, flows, rules, information | The arrangement that produces the pattern |
| Mental models | Beliefs that keep the structure in place | The assumption people act on |
| Goals/paradigm | What the system is for, or the worldview under the goal | Purpose, boundary, or the mindset that makes the goal obvious |

Do not answer an Events question with a Goals/paradigm lecture. Do not answer a repeating pattern with a single Why-chain unless the chain stays single.

## How the labels pick a page

- Frame at any layer → a framing tool. Goals/paradigm framing is still framing (eigenquestion, Cynefin, hard choice), not a systems essay.
- Diagnose at Events → a narrow diagnosis tool. Diagnose at Patterns or Structure → diagnosis plus a systems complement.
- Systems at Events → you are early. Get the beat (what repeated) before naming a loop.
- Decide → a decision tool. If the options are not yet real options, Frame first and say so.
- Prioritize → a prioritization tool. If the list is priorities across a shared constraint, Theory of Constraints is the systems-flavored one.
- Plan → a planning tool. A plan that ignores a known loop takes a systems complement.
- Communicate → a communication tool. Do not use it to avoid a decision.
